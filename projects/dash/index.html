Highlights

  • Moved the wallet off its legacy Objective-C sync layer onto a Rust core reached over a C ABI FFI — sends, swap routing, transaction matching and identity startup.
  • Redesigned the core money flows in SwiftUI — send, receive, internal transfer and a tabbed payments landing.
  • Built the notifications module end to end — dispatcher, deep-link router, persistent store, background refresh and unified read-state with search.
  • Shipped accessibility as infrastructure — a VoiceOver audit tool plus a CI ratchet that blocks any new unlabeled control.
  • Implemented dApp authorization over deep links — approve a login or purchase from a web app without scanning a QR code.

The problem

The wallet synchronised through a legacy Objective-C layer, while the team was moving every platform onto a shared Rust wallet core. The iOS app had to switch to the new core without breaking money flows that people use every day, and its UI needed a redesign.

My approach

  • Rust core over a C ABI FFI. I moved sends, swap routing, transaction matching and identity startup onto the new SDK boundary. I also contributed to the core itself (transaction building, coin selection, balance reporting, chain sync) and carried each change through the Swift and Kotlin SDKs.
  • Money flows in SwiftUI. I redesigned send, receive and internal transfer. Send-to-contact goes through the standard send pipeline, and a shared source picker is driven by the spendable balance.
  • Notifications module. I built it end to end: dispatcher, permission and lifecycle handling, deep-link router, persistent store, per-transaction producers and background refresh.
  • Shared UI package. I maintained the bottom sheets, numeric keypad, reusable cards and a themed icon set with light and dark appearances.
  • Integrations. Cross-chain swaps, a built-in DEX, staking, gift cards, a merchant directory, and privacy features for shielded, mixed transactions.

Technical deep dive: accessibility as infrastructure

A support ticket reported unlabeled tabs and buttons. An audit of the whole app found the same defect everywhere, and nothing stopped it from coming back: no lint rule, no CI check, no test.

  • Audit tool. A standard-library Python script checks the whole repository in about a second against 12 rules, each taken from a real defect: icon-only buttons, empty toggle labels, custom back buttons, tap gestures without accessibility, unlocalized labels and Dynamic Type issues.
  • A ratchet, not a gate. The existing findings are recorded in a baseline and don’t fail the build, so the team could adopt the check on day one. A pull request can’t add a new unlabeled control. The baseline is read from the base branch, so a PR can’t add a regression and baseline it in the same commit.
  • Fixing the root cause. Most issues came from five shared components: the custom back button (36 call sites), navigation-bar icons (31), settings toggles (35), amount rows that never said “Dash” (38), and the number keypad.

Outcome

  • 134 merged pull requests across four repositories: the iOS app (95), the platform SDK (14), the Rust wallet core (12) and the shared UI kit (13).
  • The accessibility audit surfaced 650+ issues across 12 rules. They were concentrated in five shared components, so fixing those five repaired an estimated 60–70 screens.
  • The CI check now runs on every pull request that touches app code, so a new unlabeled control can no longer reach a release.
